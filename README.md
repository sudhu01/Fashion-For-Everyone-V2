## App Description

Fashion For Everyone lets users describe clothing in plain text and instantly see what it looks like — both front and back — rendered as an image using a custom LoRA fine-tuned on ~348 menswear product images.

Key capabilities:

- **Conversational styling:** each chat ("Fitting") retains context, so follow-up prompts like *"now in navy"* inherit the prior garment/fit/fabric
- **Dual-view rendering:** every generation produces a front view (text-to-image) and a back view (chained image-to-image edit from the front), both sharing the same seed for visual consistency
- **Vocabulary-grounded prompts:** a sanitizer validates user input against the training vocabulary, rejects NSFW/out-of-distribution requests, extracts structured facets, and builds augmented prompts that the LoRA understands
- **Persistent history:** all chats, messages, and generated images are stored in PostgreSQL per user
- **Image magnifier:** hover over any generated image to activate a 2.5× zoom lens for detail inspection

## Workflow (Usage)

```
1. Sign up / sign in (Clerk OAuth)
         │
         ▼
2. Open or create a new "Fitting" (chat session)
         │
         ▼
3. Type a garment description
   e.g. "brown slim fit blazer with notched lapel"
         │
         ▼
4. Server sanitizes prompt
   - validates against training vocabulary
   - extracts facets: fit, garment, fabric, color, details
   - inherits missing slots from prior turn if this is a follow-up
   - builds frontPrompt + backPrompt
         │
         ▼
5. Image generation pipeline (fal.ai)
   - Front view: text-to-image (or img2img from prior turn's image)
   - Back view: image-to-image edit of the front render
   - Both use the same seed and custom LoRA (scale 0.85)
         │
         ▼
6. Results returned to browser
   - Two images displayed side by side with labels
   - Hover either image to activate magnifier lens
         │
         ▼
7. Type a follow-up (e.g. "in navy" or "add a chest pocket")
   - Prior facets are inherited where the new prompt is silent
   - Prior front image used as reference for img2img continuity
```

## Data Flow

```
USER TYPES: "brown slim fit blazer"
        │
        ▼
[Browser] ChatInput.onSend()
  - Optimistic UI: add provisional user bubble + loading state
  - POST /api/chats/[id]/messages  { content: "brown slim fit blazer" }
        │
        ▼
[API Route] POST /api/chats/[id]/messages
  1. Clerk middleware verifies session cookie
  2. requireAuth() → load or lazy-provision User row from DB
  3. rateLimit.take(userId) → reject 429 if token bucket empty
  4. zod.parse(body) → validate payload shape + length
  5. DB transaction:
       INSERT Message(role='user', text="brown slim fit blazer")
       INSERT Message(role='assistant', text='', placeholder)
       UPDATE Chat(updatedAt, title if first message)
  6. Build systemPrompt from User.profile (gender, bodyType, size, styleTags)
  7. Fetch prior turn's GeneratedImage → extract priorFacets + referenceImageUrl
  8. Call generateImage(userId, prompt, systemPrompt, messageId, chatContext)
        │
        ▼
[lib/generation.ts] sanitizeAndAugmentPrompt(rawPrompt, priorFacets)
  - Normalize + tokenize input
  - Reject: NSFW keywords, women's-only garments, non-fashion terms
  - Extract facets: { view, fit, garment, fabric, color, details[] }
  - Inherit missing slots from priorFacets (e.g. garment, fit)
  - Build:
      frontPrompt = "front view of brown slim fit blazer made from ..."
      backPrompt  = "back view of brown slim fit blazer made from ..."
  - Throw SanitizationError (user-safe message) on validation failure
        │
        ▼
[lib/generation.ts] persist + dispatch
  - INSERT Prompt(text=frontPrompt, rawUserInput, systemPrompt, params={facets,seed})
  - INSERT GeneratedImage(status='pending') × 2  (front + back)
        │
        ├──────────────────────────────────────────────┐
        ▼                                              ▼
[fal.ai] FRONT VIEW                          [fal.ai] BACK VIEW
  Model: FAL_MODEL_ID                          Model: FAL_I2I_MODEL_ID
  Mode:  t2i (or i2i if referenceUrl exists)   Mode:  i2i (input = front result)
  Payload:                                     Payload:
    prompt: frontPrompt                          prompt: backPrompt
    loras: [{path: LORA_URL, scale: 0.85}]       loras: same
    num_inference_steps: 4                       image_url: frontImage.url
    guidance_scale: 1.0                          seed: same shared seed
    seed: <shared seed>                          enable_safety_checker: true
    image_size: "portrait_4_3"
    enable_safety_checker: true
  → queue submit → poll every 2s → fetch URL   → queue submit → poll → fetch URL
  → validate URL (https, whitelist, no LAN IPs)
  → UPDATE GeneratedImage(status='completed', url)
        │                                              │
        └───────────────────────┬──────────────────────┘
                                ▼
[API Route] finalize
  - UPDATE assistant Message(text, frontImageUrl, backImageUrl)
  - Return JSON { userMessage, assistantMessage, chat }
        │
        ▼
[Browser] ChatPage
  - Replace provisional message with server version
  - MessageList renders:
      assistant bubble → text reply
                       → 2-column grid: MagnifierImage(front) | MagnifierImage(back)
  - Sidebar updates chat title
  - User can follow up: "now in navy" → inherits blazer/slim/viscose from this turn
```

## Tech Stack

| Layer | Technology |
|---|---|
| Framework | Next.js 14 (App Router, React 18, TypeScript) |
| Styling | Tailwind CSS 3.4 |
| Auth | Clerk 6 (OAuth, session cookies, webhooks) |
| Database | PostgreSQL + Prisma ORM 5 |
| AI / Image Gen | FLUX.2 Klein via fal.ai queue API |
| Custom LoRA | `fashion_for_everyone_v1.safetensors` (82 MB, trained on 348 captions) |
| Webhook verification | Svix (Clerk → DB user sync) |
| Input validation | Zod 3 |
| Rate limiting | In-memory token bucket (per user) |
| Dataset scraper | Python + Playwright (Zara product pages) |

## Setup & Deployment

### Prerequisites

- Node.js 20+, pnpm
- PostgreSQL database
- Clerk account (auth)
- fal.ai account (image generation)
- LoRA weights hosted on Hugging Face or S3

### Web App

```bash
cd web
pnpm install
cp .env.example .env.local   # fill in all variables
pnpm run db:migrate          # apply Prisma migrations
pnpm dev                     # local dev server
pnpm build && pnpm start     # production
```

### Database commands

```bash
pnpm run db:migrate   # generate + apply migrations locally
pnpm run db:deploy    # apply existing migrations (production)
pnpm run db:studio    # open Prisma Studio
```

### Dataset scraper (Python)

```bash
python -m venv .venv
source .venv/Scripts/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cd dataset-scraper
python zara.py
```

```bash
# Image Generation (fal.ai)

FAL_MODEL_ID="fal-ai/flux-lora"        # Text-to-image model
FAL_I2I_MODEL_ID="fal-ai/flux-lora/image-to-image"  # Img-to-img (back view)
LORA_URL="https://..."                 # URL to LoRA safetensors file
LORA_STRENGTH="0.85"                   # LoRA scale (0–1)
FAL_STEPS="4"                          # Inference steps (FLUX Klein = 4)
FAL_GUIDANCE="1.0"                     # Guidance scale (distilled model)
FAL_IMAGE_SIZE="portrait_4_3"
FAL_TIMEOUT_MS="300000"                # Max ms to wait for generation
FAL_POLL_MS="2000"                     # Polling interval

# Rate Limiting
RATE_LIMIT_CAPACITY="10"
RATE_LIMIT_REFILL_PER_SEC="0.1"
```
